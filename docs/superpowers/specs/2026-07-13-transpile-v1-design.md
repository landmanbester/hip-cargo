# `hip-cargo transpile` v1 — Design

**Status:** Approved (user, 2026-07-13). EPHEMERAL: fold into `docs/wiki/transpile.md` and delete before merge.
**Branches:** hip-cargo `apis`; stokify `transpile`.

## Decisions (user-approved)

1. **In-memory dataflow via the `_inmem` sibling convention** — no cab-schema change; disk-faithful fallback when no sibling exists.
2. **Output target: a new `src/stokify/transpiled/` subpackage** beside the hand-written `runtime/` exemplars (which stay as the diffable reference).

## Command

`hip-cargo transpile RECIPE.yml --output-dir DIR [--package PKG]` — `cli/transpile.py` (thin, lazy) + `core/transpile.py`. Core-install only (pyyaml + libcst); reuses `monitoring/recipe_parser.py` + `cab_resolver.py` as the single parser front-end (verify `hip_cargo.monitoring` imports stay light; fix laziness if not). Requires the target package importable (lightweight install suffices — source on disk, no heavy imports).

## Pipeline: parse → validate → infer → emit

**Parse:** `parse_recipe(path, resolve_cabs=True)` → `RecipeDAG`.

**Validate** (collect ALL errors, then exit 1; each names the feature + RFC §6 exclusion):
- binding expression not exactly `recipe.<known-input>` (formula DSL / unknown ref)
- recipe input `aliases` non-empty
- step keys `for_loop`/`scatter`/`recipe` (nested) present
- cab flavour not `python` / cab unresolvable
- required cab input neither bound in step params nor defaulted

**Infer:**
- *Data edges:* producer output binding string == consumer input binding string (raw equality).
- *In-memory:* resolve cab `command: pkg.mod.fn` via `importlib.util.find_spec` (no execution), libcst-scan source for `def fn_inmem`. Found → inmem call; verify signature starts with the contract slots; else clear error. Absent → disk-fallback call of declared command with lowered paths.
- *Contract:* `fn_inmem(upstream_dataset?, memory_mode, job_id, pipeline_run_id, work_dir, **cab_params)`; upstream positional only when the step has an incoming data edge; transpiler passes `job_id` as `pipeline_run_id` too.
- *Param mapping (inmem):* all path-dtype (File/Directory/MS/URI) bindings dropped; cab input named `memory-mode` fills the `memory_mode` slot (constant `"greedy"` if the recipe has none); `work_dir` = the unique recipe input referenced by the step's dropped path bindings (error if ambiguous); remaining bindings become kwargs (hyphens → underscores).
- *Interpolation lowering* (fallback mode + tests): `'{recipe.base-dir}/init.zarr'` → `f"{base_dir}/init.zarr"`.

**Emit** to `--output-dir` (`__init__.py`, `tasks.py`, `runner.py`, `cli.py`), each headed `# Generated by hip-cargo transpile — do not edit.` + source recipe path; ruff format/check --fix subprocess (cwd = output package root's project dir); byte-compare-before-write idempotence:
- `tasks.py`: one `@ray.remote` per step (explicit typed signature: upstream?, memory_mode, job_id, work_dir, monitor, kwargs); body = `_activate_backend()` if monitor → timed lazy import → `annotate_diagnostics(import_s=…, requested={"num_cpus": 1}, memory_mode=…)` if monitor → inmem call. `runtime_env` constants only when cab declares `image` (stokify's don't). No per-step resources in v1 (nowhere to declare them; RFC §9.3 deferred — wiki-tracked).
- `runner.py`: `STEPS`/`EDGES` constants; `run_pipeline(<recipe inputs sanitised, defaults>, monitor=False, job_id=None, ray_address=None)`; `ray.init(address=…, namespace="<root package>", ignore_reinit_error=True)`; backend registration when monitored; `os.makedirs` for Directory inputs with `mkdir: true`; `PIPELINE_STARTED`(DAG in extra)/`STEP_STARTED`/`STEP_COMPLETED`/`COMPLETED` events; ObjectRef chain in declaration order with `ray.wait` per step; returns `(job_id, final_ref)`.
- `cli.py`: Typer `run` from recipe `inputs:` reusing `generate_parameter_signature`, + `--monitor/--job-id/--ray-address`; module-level `app = typer.Typer()`.

## stokify integration (branch `transpile`)

- Committed generated output at `src/stokify/transpiled/`.
- `stokify transpiled run` registered in `cli/__init__.py`.
- Structural-equivalence test vs hand-written exemplars (same STEPS, EDGES, inmem targets).
- Slow e2e test: transpiled runner, tiny synth sizes, monitored; assert lifecycle events + diagnostics report fields.
- `demo.py --transpiled` drives the generated runner.
- README section: what transpile does, the four stages, the inmem contract, regeneration command, diff invitation (`runtime/` vs `transpiled/`).

## Testing (hip-cargo)

Fixture recipes under `tests/fixtures/transpile/`: valid linear (mirrors stokify against a tiny fake package fixture), each refusal case, no-inmem fallback. Unit: validation messages, edge inference, contract mapping, f-string lowering, golden-file snapshot of emitted modules, idempotence (mtime preserved), emitted code passes `ruff check`; `bandit` via `importorskip`.
