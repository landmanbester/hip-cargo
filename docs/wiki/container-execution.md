# Container execution and image lifecycle

Source: `src/hip_cargo/_container_image.py`, `utils/config.py` (readers),
`utils/runner.py` (fallback execution).

## `_container_image.py` — single source of truth

Each hip-cargo-style package declares its container image in a
`_container_image.py` module: `CONTAINER_IMAGE` (URL:tag), optional `GPU`
(`True` / `False` / `"auto"` / a device spec like `"device=0,1"`), and
optional `RUN_ARGS_DOCKER` / `RUN_ARGS_PODMAN` / `RUN_ARGS_APPTAINER` /
`RUN_ARGS_SINGULARITY` (lists, default `[]`). Readers in `utils/config.py`
(`get_container_image`, `get_container_gpu`, `get_container_run_args`) load it
via `importlib` — no CWD dependency, no `uv sync` needed after edits. None of
this appears in cab YAML; the round-trip is untouched.

**Tag lifecycle** — three mechanisms keep the tag in sync:

1. **Feature branches**: developer sets the tag to the branch name by hand
   (this branch: `:apis`).
2. **Merge to main**: the `update-cabs` workflow resets the tag to `latest`
   via regex, regenerates cabs, commits with `[skip checks]` (custom tag:
   CI runs but skips heavy steps so required checks still report success).
3. **Releases**: `tbump` writes the semantic version via before-commit hooks
   in `tbump.toml`. Changelog is auto-generated by git-cliff from
   conventional-commit prefixes (`cliff.toml`).

Gotcha: the `generate-cabs` pre-commit hook regenerates cab YAML with the
*installed* hip-cargo and can wrongly flip a feature branch's tag back to
`:latest`. On feature branches, restore `src/hip_cargo/cabs/` and commit with
`SKIP=generate-cabs` for non-code commits.

## Container fallback

Generated CLI wrappers lazy-import the core function inside
`try/except ImportError`; on failure `run_in_container()` reconstructs
`sys.argv` and re-runs the command in the package's container. Backend
priority: `apptainer` → `singularity` → `docker` → `podman`. Volume mounts
resolve automatically from Path-like type hints (ro) and `@stimela_output`
decorators (rw). Cabs with an `image` field get generated `--backend`
(`auto|native|apptainer|singularity|docker|podman`) and
`--always-pull-images` params, both `{"stimela": {"skip": True}}` so they
never reach cab YAML.

## GPU passthrough

`run_in_container` reads `GPU` via
`get_container_gpu(func.__module__.split(".")[0])`, resolves through
`_resolve_gpu_request` (env `HIP_CARGO_GPUS` overrides the constant; `"auto"`
adds flags only when `_gpu_available()` and, for docker/podman,
`_toolkit_available()`), then maps per runtime via `_gpu_args`:

| Runtime | Mechanism |
|---------|-----------|
| docker | `--gpus` (bare index lists normalised to `device=` form) |
| podman | CDI `--device nvidia.com/gpu=...` (host needs `nvidia-ctk cdi generate`) |
| apptainer/singularity | `--nv`; device specs become `CUDA_VISIBLE_DEVICES` |

Host `CUDA_VISIBLE_DEVICES` is forwarded. Explicit device specs target
docker and apptainer/singularity; on podman prefer `True`/`"auto"`/`"all"`
(CDI uses a different device grammar).

## Per-backend run-args

`RUN_ARGS_<BACKEND>` lists are inserted verbatim right after the `run`/`exec`
subcommand for the active runtime. Env `HIP_CARGO_RUN_ARGS` (shlex-split)
appends to whichever backend runs.
