# `hip-cargo transpile`

Compiles a restricted-subset stimela recipe into an auditable Ray runner
package (rationale: `docs/design/transpile-rfc.md`). **Status: v1** —
linear recipes, single package, demonstrated end-to-end on stokify.
This page tracks the implemented state as the command evolves; check
`last_verified_commit` before trusting details.

Source: `src/hip_cargo/core/transpile.py` (validate → IR → codegen),
`src/hip_cargo/cli/transpile.py`. Core-install only (pyyaml + libcst); the
parser front-end is shared with monitoring (`recipe_parser.py`,
`cab_resolver.py`).

## Usage

```bash
hip-cargo transpile --recipe src/stokify/recipes/stokify.yml \
                    --output-dir src/stokify/transpiled
# --package overrides the emitted dotted path (default: <root pkg>.<dir name>)
```

Requires the cab package importable (lightweight install suffices — modules
are located but **never imported**). Output is idempotent: unchanged files
are not rewritten.

## Pipeline

1. **Parse** — `parse_recipe(path, resolve_cabs=True)` → `RecipeDAG`.
2. **Validate** — collects *all* violations, exits 1 naming each (see grammar
   table). This is the migration story: point it at any recipe and get the
   full distance to the subset.
3. **Infer** — *data edges* from matching output↔input binding strings
   (replacing the parser's linear-only edges); *in-memory siblings* detected
   statically: `importlib.util.find_spec` locates the module, LibCST scans
   its source for `def <command>_inmem` — the science stack is never loaded.
4. **Emit** — `__init__.py`, `tasks.py` (one `@ray.remote` per step, timed
   lazy import + `annotate_diagnostics`), `runner.py` (ObjectRef chain,
   lifecycle events, `mkdir` handling), `cli.py` (Typer `run` from recipe
   `inputs:` via `generate_parameter_signature`, plus
   `--monitor/--job-id/--ray-address`). All ruff-formatted; each file headed
   "Generated by hip-cargo transpile — do not edit."

## Accepted grammar (v1)

| Construct | Status |
|-----------|--------|
| Linear steps, python-flavour cabs | accepted |
| Literal params, `=recipe.x` refs, `{recipe.x}` interpolations | accepted |
| Consumer without `_inmem` sibling | accepted (disk-fallback call of the declared command) |
| Formula DSL (`=IF`, `=IFSET`, arithmetic) | refused: `formula-dsl` |
| Input `aliases` | refused: `aliases` |
| `for_loop` / `scatter` / nested recipes / any extra step key | refused: named after the key |
| Non-python cab flavours | refused: `non-python-cab` |
| Unknown `recipe.*` refs; unbound required cab inputs | refused: `unknown-ref` / `unbound-required` |
| Multiple upstream producers for one step | refused: `multiple-upstreams` (linear v1) |

## The v1 in-memory contract

A cab command `pkg.mod.fn` opts into ObjectRef chaining by providing a
sibling in the same module:

```python
def fn_inmem(dataset, memory_mode, job_id, pipeline_run_id, work_dir, **cab_params): ...
#            ^ first positional only when the step consumes an upstream output
```

- The transpiler passes `job_id` for both `job_id` and `pipeline_run_id`.
- All path-dtype (File/Directory/MS/URI) bindings are dropped from the call;
  `work_dir` is the unique recipe input the step's path bindings reference
  (ambiguity is refused: `ambiguous-work-dir`).
- A cab input named `memory-mode` fills the `memory_mode` slot (literal
  `"greedy"` when the recipe has none). Remaining bindings arrive as kwargs
  (hyphens → underscores); extra function params keep their defaults.
- Signature deviations are refused with `inmem-contract`.

## Deferred (tracked here as they land)

- **Per-step resources** (`num_cpus`/`num_gpus`/`memory` on `@ray.remote`) —
  no cab/recipe field carries them yet (RFC §9.3); tasks currently annotate
  `requested={"num_cpus": 1}` (Ray's default).
- **Applying `runtime_env` `image_uri`** — constants are emitted only when a
  cab declares `image`; the experimental per-task container path is a
  separate validation milestone (RFC §11).
- **`for_loop` / `scatter` / nested recipes** — IR shapes sketched in RFC §12
  stage 4, not built.
- **Standalone installable package output** (RFC §9.5) and the emitted
  frontend (RFC §5.9).
